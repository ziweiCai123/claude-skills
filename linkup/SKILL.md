# 关联 linkup — 人物关联推理

找出两个真实人物之间的**真实社会联系路径**(类似"六度分隔"游戏)。每跳必须可验证,**绝不编造关系**——这是本 skill 的第一原则,宁可诚实报告"找不到",也不臆造联系链。

本 skill 只处理**有公开信息的真实人物**(公众人物、历史人物、有新闻报道/百科条目的人)。不查询私人关系、不挖普通人的隐私。

## 配置(换路径只改这里)

- 验证规则参考:`linkup\references\verification.md`
- 输出格式参考:`linkup\references\output-template.md`
- WebSearch 总预算:**≤ 10 次**
- 最大跳数:**5 跳**(5 条边 = 6 人链条,对应经典"六度分隔")

## 联系类型(什么算"一跳")

下列真实社会联系都算一条边:

- **共同出演影视**(同一部电影的 cast/crew、同一部剧的同一季)
- **合作创作**(同一首歌、同一本书、同一款游戏)
- **同事**(同一家公司或同一个项目的核心成员)
- **校友**(同一所学校的同一时期)
- **亲属 · 婚姻**(血缘、姻亲、公开伴侣关系)
- **同一具体事件**(同一届颁奖典礼、同一集节目、同一次婚礼/峰会/演出)
- **同组织成员**(同一政党、同一学会、同一宗教组织、同一基金会)
- **商业合作**(共同投资、合伙人、董事会共事、公开的商业伙伴)
- **师生 · 导师**(明确的指导关系)
- **队友 · 同一战队**(球队、电竞战队、乐队成员)

**硬约束**:只是"同时代同行业"不算边——必须有**具体共同实体**(作品名 / 公司名 / 事件名 / 组织名)。禁止把"都上过同一档节目但不同集""都参加过同一活动但不同年"算作边;必须**同一集 / 同一届 / 同一次**。

## 先判断用哪种模式

- 两个名字 + 要找路径(`/linkup A B`、"A 和 B 什么关系"、"查一下 A 和 B 的联系"、"A 怎么认识 B"、"他们怎么连起来")→ **模式 1(完整路径)**
- 只有一个名字(`/linkup A`、"A 的关系网"、"A 关联谁")→ **模式 2(单人关系网)**
- 问"是否认识"("X 和 Y 认识吗"、"A 和 B 见过吗"、"X 认识 Y 吗")→ **模式 3(认识判定,模式 1 的子集,只到 2 跳)**

## 模式 1 · 完整路径搜索 `/linkup A B`

**动手前先 Read** 这两个参考文件(按需):
- `linkup\references\verification.md` — 验证硬规则、置信度定义、query 模板、跨文化策略
- `linkup\references\output-template.md` — 输出格式

按以下顺序执行:

### 步骤 1 · 消歧与可查性

对 A、B 各 WebSearch 一次(预算 2 次),判定:
- **同名多名人**(搜出多个同名公众人物)→ 问用户"指哪位?给出职业/年代区分",确认后再继续。
- **普通人**(0 个可靠公开结果)→ 直接回答"X 无公开信息,本 skill 不查询私人关系",**结束**。不要硬查。
- **唯一明确人物** → 进入步骤 2。

跨文化人物搜名策略见 verification.md(中文人物加拼音、西方人物用原名、日韩人物用罗马音+原文)。

### 步骤 2 · 一行领域画像

为 A、B 各写**一行**领域画像(职业 + 主要活跃领域与年代 + 1-2 个最知名的关联实体)。不要展开成长篇——画像只是给步骤 3 的搜索提供方向,深度画像烧 token 且大部分用不上。

### 步骤 3 · 分层路径搜索(L1 → L4)

**维护 visited 集合,禁止重复节点。总预算 ≤ 10 次 WebSearch(步骤 1 已用 2 次,本步剩 8 次)。**

**L1 · 直接联系**(预算 0-1 次)
默想 A 和 B 的交集:同片 / 同公司 / 同校 / 同事件 / 亲属 / 商业合作。
- 命中且模型置信度 ≥ 中 → 进步骤 4 验证。
- 无命中 → 进 L2。

**L2 · 共同邻居启发式**(预算 2-4 次)
按优先级只挑 **2 个**候选维度展开(根据步骤 2 画像选最可能的):
(a) 同影视 cast  (b) 同公司董事会/高管  (c) 同大学校友  (d) 同一具体事件(同一届典礼/同一集节目/同一次峰会)  (e) 同行业同时代的跨界枢纽
对每个候选共同邻居 N,两条边 A-N 和 N-B **一起生成、一起验证**。命中 → 进步骤 4。否则进 L3。

**L3 · 中介枢纽**(预算 3-5 次)
从 A 的高知名度合作者中挑 **2-3 个**"高跨界度枢纽"(横跨多行业、人脉广者),对每个 M 检查 M-B 是否有真实联系。命中 → 进步骤 4。否则进 L4。

**L4 · 失败处理**
诚实报告"5 跳内未找到可靠路径",**列出 L2/L3 最近的 miss 候选**(差一点就连上的人),让用户知道"差在哪"。**绝不编造**路径凑数。提示"可能存在更短路径,但模型知识 / 搜索预算不足以发现"。

### 步骤 4 · 边验证(WebSearch 硬规则)

每条候选边必须满足下列之一才能进最终输出:

- **[核实]** WebSearch 返回 ≥1 个可靠来源(维基 / 新闻 / IMDB / 官网 / 公开档案),明确提到 A 和 B + 具体共同实体 + 理想年份。
- **[确信]** 模型从训练知识高度确信(如"汤姆·汉克斯主演《阿甘正传》"),仅作辅助,**不可作为最终链的唯一依据**。
- **[待核]** 其他一切。

**硬规则(必须遵守)**:
- 最终输出链条**禁止出现 [待核] 边**。遇 [待核] 必须先 WebSearch 升级,否则丢弃换路径。
- L2、L3 阶段生成的每条边**默认 [待核]**,验证后才能进输出。
- 禁用"可能 / 据传 / 有人称 / 应该 / 疑似 / 听说"等模糊词。无法核实 = 丢弃。
- 禁止从"同时代同行业"推断联系——必须有具体共同实体。
- 禁止"同节目不同集""同活动不同年"算边——必须同一集 / 同一届 / 同一次。

WebSearch query 模板和跨文化策略见 verification.md。

### 步骤 5 · 输出链条

照 output-template.md 的**长链格式**输出。每跳显示:联系类型 + 具体共同实体 + 年份(如有)+ 置信度 + 来源链接。末尾给跳数统计和(若适用)未找到更短路径的原因。

## 模式 2 · 单人关系网 `/linkup A`

展开 A 的核心合作者/关联人清单。流程:
1. 步骤 1 消歧(同模式 1)。
2. WebSearch A 的关联信息 1-2 次,列出 **5-8 个**最高知名度的关联人,按关系类型分组(合作者 / 同事 / 亲属 / 同事件...)。
3. 每条标注 [核实](搜到的)或 [确信](模型高度确信的常识,如"乔布斯与沃兹尼亚克共同创立苹果")。
4. 输出成清单,不要长链格式。

---

## 模式 3 · 二人是否认识 `/linkup X Y 认识吗`

模式 1 的子集,只搜到 **2 跳**。流程:
1. 步骤 1 消歧(同模式 1)。
2. 只跑 L1(直接联系)+ L2 一层(共同邻居)。
3. 输出**判定 + 证据**:
   - 找到 ≤2 跳联系 → "认识(通过 Z)"或"有联系(通过 Z)",给链条。
   - 未找到 → "未发现公开的 2 跳内联系",**不要**断言"绝对不认识",只说"未发现"。

---

## 边界

- **同名名人**:步骤 1 搜出多个 → 问用户"指哪位?",确认后继续。
- **普通人(无公开信息)**:步骤 1 搜出 0 个可靠结果 → 明确告知"无公开信息,本 skill 不查私人关系",**退出**。不要臆造。
- **跨语言/跨文化人物**:中文人物加拼音、西方人物用原名、日韩人物用罗马音+原文(见 verification.md)。
- **历史人物**:同流程;接受 [确信] 边的门槛略宽(古典人物事实训练较充分,如"李白与杜甫同时代诗人"——但仍需具体共同事件/作品才算边,仅"同时代"不够)。
- **在世人物**:流程一致;近期事件 WebSearch 覆盖更好,优先用近期合作核实。
- **找不到路径**:显式说"X 跳内未找到可靠路径",列最近 miss 候选,不强行凑。
- **5 跳上限触达**:硬上限,超过即报失败,提示"可能存在更短路径但知识/预算不足"。

---

## 失败时要诚实

本 skill 最重要的是**不编造**。任何无法用 WebSearch 或高度确信常识核实的关系,都要丢弃。宁可回答"5 跳内未找到",也不要输出一条含 [待核] 边的虚假链条。用户要的是真实联系,不是看上去合理的编造。
