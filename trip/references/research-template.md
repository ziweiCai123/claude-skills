# 调研情报结构化模板

核心原则: **信息只有落进结构才有价值**——WebSearch 结果和用户粘贴的笔记,当轮解析进结构,不留散信息。(对应场景规律: 用户最大痛点是"信息过多难筛选",规划者的价值就是筛选+结构化。)

## 攻略阅读的提取维度（读任何攻略时问这五个问题）

1. **动线**: 走什么环线? 各段车程多少? 哪天在赶路?
2. **选择**: 作者去了哪/放弃了哪? 放弃的理由是什么(距离/体力/不值)?
3. **节奏**: 作者后悔哪天排太满? anchor 是什么?
4. **钱**: 门票/车费/餐饮的真实价格(价格是强信任信号)
5. **坑**: "千万别/后悔/下次不"——每一条都是风险卡素材

## 攻略检索的产出物

### 1. 动线骨架表
```
经典环线: 贵阳(D1) → 黄果树(D2) → 荔波(D3-4) → 西江(D5) → 返(D8)
各段车程常识值: 贵阳→黄果树 115min / 兴义→荔波 300-330min ...
```
用途: hubs.json 的初始值(后续被高德真实值覆盖)。

### 2. POI 评分卡(多源交叉校准)

| 来源信号 | 分数动作 |
|---|---|
| 两篇独立笔记都顶格夸("此行最佳/只能推一个") | score +12 |
| 小红书⭐⭐⭐⭐⭐"超强推" | score ≥ 85, 考虑 must |
| 笔记"不值得/避雷/可玩不多" | score -10, 通常排除出池 |
| "不值得特意去/路过顺路" | score 60-70, allowed_days 顺路日 |
| 小众差异化点(免票/零商业/本地人推) | 加池, 即使 score 中等(多样性维度奖励) |
| 孤证(只有一篇提到的好评) | 进 notes 不进 score |

### 2.5 锚点识别(对应 anchor 法)

读完所有材料后自问: **这个目的地"错过会后悔"的是哪 2-5 个?** 它们是 must 候选+排程时保上午位。攻略里反复出现、作者放最前面讲、配图最多的,就是 anchor。

### 3. notes 字段素材(逐点搬运,渲染进作战卡)
- 玩法: "不买票,村里租电瓶车" / "东门进坐车到西门反着玩=全程下坡"
- 机位/时刻: "7点大桥拍雾" / "观景台看夜景"
- 体力: "上半程可跳过,精华在下半段"
- 避坑: "别买20元无限次观光车" / "5元单程随上随付"

### 4. 美食清单(food_stop.json 素材)
每城: 必吃(菜名+店铺+价格+一句话) / 避坑(黑名单) / 优先级(★★★必吃~猎奇可选)

## 小红书粘贴文本的解析规则

1. ⭐计数 → priority/score 映射(见上表)
2. 店名+价格 → shop/price 原样保留(价格是强信号,用户对"9.9元"有信任感)
3. "不要/千万别/避雷" → blacklist 或 notes 警示
4. "雨天...反而/特别" → weather: rain_ok 依据
5. 时段信号("傍晚光线好/清晨无人") → open_min/close_min 调整依据
6. 不可验证的孤证(只有一篇提) → 进 notes 不进 score

## 风险检索的产出物(risk_plans.json 素材)

- "{景点} 关闭/停开"检索: 找到历史关闭案例 → R卡 scenario 写机制("落石/水淹/水雾管制"), 不写空泛的"可能关闭"
- 预约规则: 平台名/提前天数/放票时间 → 预约清单+R3卡
- 交通瓶颈: 返程高峰/加油站稀疏段/限速陷阱 → 驾驶卡
