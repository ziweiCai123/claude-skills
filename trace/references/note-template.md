# 每日笔记模板

文件名：`YYYY-MM-DD.md`（本地日期）。每篇笔记 = **YAML frontmatter**（给 aggregate.py 读）+ **正文**（给人读）。
frontmatter 是统计的唯一数据源，字段必须填全。

> **Obsidian 协作**：daily note 是给自己看的，技术名用 `[[]]` 双链（如 `[[Docker]]`）、日期引用也用双链（如 `[[2026-06-30]]`）——在 Obsidian 里能形成知识图谱、聚合到同一技术页。**日报/周报（reports/）不用双链**，保持纯文本（要 copy 进企业系统）。

## frontmatter

```yaml
---
date: 2026-07-03
technologies: [Docker, WSL2, git]   # 今天接触的技术/工具名列表
domains: [计算机]                    # 今天涉及的领域/主题；跨领域时多个，如 [计算机, 生物医学]
questions: 3                        # 今天问过的代表性问题数
mistakes_resolved: 2                # 已解决的踩坑数
mistakes_total: 3                   # 踩坑总数（含未解决）
struggle: medium                    # low / medium / high
summary: "一句话总结今天的学习"
sessions: 1                         # 今天 /trace 的次数（合并时 +1）
tags: [type/daily]                  # Obsidian/Dataview 类型标签
---
```

## 正文结构（两种形态，按今天是否跨领域选）

- **形态 A · 单主题**（绝大多数，如只搞了前端 / 只调一个 bug）：按 section 横切，下面默认结构。
- **形态 B · 多主题**（明显跨不相关领域，如上午计算机、下午生物医学）：用「主题分区」——`## 📂 主题名` 二级标题把每个领域包成一块，每块内再放学到了 / 踩坑 / 反思。frontmatter 的 `domains` 记录全部领域，`technologies`/`mistakes` 仍记全天总数。
- **判断**：领域差异大才分区（计算机 vs 生物医学、前端 vs 运维）。同领域的不同技术（Docker + git）不要硬分，否则过度切碎。

没内容的 section 可省略。

多主题形态下，「🔗 与过去的连接」「✨ 三段反思」放进**各自主题块**内（每主题有自己的）；「📚 明天试试」「🔁 该复习了」放底部**跨主题统一**。

## 合并规则（同天再次 /trace）

frontmatter：technologies、**domains** 取**并集**、questions/mistakes_resolved/mistakes_total **相加**、sessions **+1**。
正文：
- **单主题天**：各 section **追加**本次新内容（可加 `### 会话 2` 子标题区分）。
- **多主题天**：本次会话属于**已有主题** → 并入该主题块；属于**新主题** → 新开一个 `## 📂 新主题` 块。
- **单 → 多主题升级**：本次引入新领域时，把原横切内容归到一个主题块、新领域另起一块，整体转成形态 B。
`<!-- user-notes -->` 区**原样保留**不动。
