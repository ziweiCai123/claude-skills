# 日报模板（工作汇报，正式书面语）

文件名：`YYYY-MM-DD.md`，放在 `NOTES_REPO\reports\`（与周报同目录，按天命名）。
**与 daily note 的区别**：daily note 给自己看（学习/游戏化/反思）；**日报是交给企业或导师的正式工作汇报**——正式书面语、客观，**绝不出现** confidence / 徽章 / 挣扎度 / "踩坑" / "搞懂" 等内部或口语表达。

**使用场景**：用户会直接 copy 日报贴进企业管理系统（钉钉 / 飞书 / 企业微信 / 邮件 / Jira / 工单）。不同系统偏好不同格式，所以**默认在同一文件里提供多个版本，用户挑一个 copy**。

## 书面语要求（最重要）

- 用职场书面词：**完成 / 推进 / 梳理 / 对接 / 落地 / 解决 / 协同 / 验证 / 优化**
- 禁用口语和 trace 内部黑话：「搞懂了 / 踩坑 / 卡住 / 折腾 / confidence / 徽章 / 挣扎度 / 攻克」一律不出现
- 客观、结果导向，动词开头
- 不带情绪、不带反思、不暴露内部学习过程

## frontmatter

```yaml
---
date: 2026-07-03
technologies: [Claude Code, Python]   # 当天涉及技术栈
items_done: 3                          # 今日完成条目数
problems_open: 0                       # 待协调 / 未完成数
generated: 2026-07-03
tags: [type/report-daily]           # Obsidian/Dataview 类型标签
---
```

## 数据提炼（daily note → 日报素材）

先从当天 daily note 提炼出 4 类素材（都用正式书面语），再分别套进各版本：

| 素材 | 来自 daily note |
|---|---|
| 今日完成 | 「今天学到了/做过了」+ 已解决踩坑 → 正式书面语 |
| 进行中/未完成 | 未解决踩坑 + 跨天事项 |
| 需协调/存在问题 | 未解决 + 需资源支持 |
| 明日计划 | 「明天可以试试」→ 正式书面语 |

## 默认提供 4 个版本（同一文件内，用户挑一个 copy）

**除非用户在对话里指定了只要某一版**，否则四个版本都生成，放在同一个 `.md` 文件里，用 `---` 分隔，每个版本前标注适用场景。顺序按信息量递减：分点（全量）→ 段落（全量）→ 亮点要点（精炼）→ 简版（一句）。

### 版本一 · 分点汇报（默认推荐）

适合：工单系统、Jira、邮件、飞书文档等结构化场景，需要列全今日完成项。

```markdown
## 工作日报 · 2026-07-03

**今日完成：**
- 完成 ……
- 推进 ……
**进行中 / 未完成：** 无
**需协调 / 存在问题：** 无
**明日工作计划：**
- 推进 ……
```

### 版本二 · 段落汇报（一段话）

适合：钉钉 / 企业微信 / 飞书消息框、邮件正文——不便用分点、需要连贯文字的场景。
写法：用"；"串联，客观陈述，不分点、不强制换行（两三句即可）。

> 今日主要完成 ……，并推进 ……；同步解决 …… 问题。进行中事项与需协调问题暂无。明日计划推进 ……，并开展 ……。

### 版本三 · 亮点要点（高度概括，只挑最有价值的）

适合：给领导 / 导师的重点汇报、周会口头、需要突出亮点而非流水的重要场合。
写法：**只挑今天最有价值的 2-3 点**（不是全部完成项），每点一句话高度概括，动词开头、结果导向。宁少不滥——把含金量最高的摆出来，次要的不写。

> **今日重点：**
> - 完成 ……（最具分量的那件）
> - 推进 ……（次重要）
> - 解决 ……（关键卡点）

### 版本四 · 简版（一句话 / 极简）

适合：站会口头汇报、群里一句话、字数受限的系统。

> 今日完成 ……；明日计划 ……。

## 书面语转译示例

| daily note 原文（口语/内部） | 日报书面语 |
|---|---|
| 搞懂了 Docker 多阶段构建，镜像从 1.2G 降到 180M | 完成 Docker 镜像多阶段构建改造，镜像体积由 1.2GB 优化至 180MB |
| 踩坑：permission denied，volume 权限问题，解决了 | 解决容器存储卷权限异常问题 |
| 折腾了半天 pydantic API 弃用报错 | 排查并修复 pydantic 版本升级导致的接口兼容性问题 |
| struggle 高的一天 | （不出现——日报不写挣扎度） |

## 用户指定单一版本

若用户说"段落式日报" / "简版日报" / "亮点日报" / `/trace daily 段落` / `/trace daily 简版` / `/trace daily 亮点`，**只生成指定那一个版本**，不出多版本（省得文件冗长）。

## 重生成规则

同一天重复 `/trace daily` → **覆盖正文**（按最新 daily note 重新转译、重出各版本），但 `<!-- user-notes -->` 区**原样保留**。
